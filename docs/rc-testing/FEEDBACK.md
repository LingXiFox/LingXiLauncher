# 反馈指南（v0.10.0-rc.1）

RC 版本的目的就是把问题找出来，任何异常都值得报，不用先自己排查。

## 反馈渠道

- 首选：GitHub Issues <https://github.com/LingXiFox/LingXiLauncher/issues>
- 不方便公开的内容（例如包含存档片段、服务器信息）可以只贴诊断信息里与问题相关的部分。

## 报问题前做两件事

1. **复制诊断信息**：崩溃报告窗口或实例工具 →「崩溃诊断」→「复制诊断信息」。内容包含启动器版本、操作系统、Java、Minecraft 版本与加载器、六项健康检查、最近崩溃堆栈和日志尾部。
2. **确认哪些信息被脱敏**：诊断信息在离开启动器之前会经过脱敏，Access/Refresh Token、Cookie、密码、`/Users/<用户名>` 形态的家目录都会替换成占位符。粘贴前请自己再扫一眼。

启动器不会自动上传任何日志或诊断信息，只有你主动复制、主动提交时才会离开本机。

## 日志在哪

- 崩溃报告：实例目录下的 `crash-reports/`
- 游戏日志：游戏目录下的 `logs/latest.log`
- 启动器日志：数据目录的 `logs/`（设置页「打开日志目录」直达）

贴日志时截取报错前后各 30 行就够，不用整份上传。

## 分诊参考

| 现象 | 大概率原因 | 先看 |
| --- | --- | --- |
| 打不开 / 提示损坏 | Gatekeeper / SmartScreen | KNOWN-ISSUES.md KI-01、KI-02，INSTALLATION.md |
| 登录后立刻退回未登录 | 浏览器回调被拦截 | KI-10 |
| 启动卡在下载 | 网络或镜像问题 | 诊断页「游戏文件」「磁盘空间」 |
| 启动崩溃 | Java 版本 / 模组冲突 | 诊断页「Java 运行时」「日志分析」 |
| 界面空白 | 显卡驱动 / WebKitGTK | 终端启动看输出，附诊断信息 |

## 修复节奏

RC 期间按「能复现 → 定位 → 修复 → 进入下一个 RC」推进；影响启动的阻塞问题优先，UI 细节排在后面。
